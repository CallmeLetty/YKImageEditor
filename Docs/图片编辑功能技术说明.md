# 图片编辑功能技术说明

本文档说明 YKImageEditor 当前各项图片编辑功能的实现方式、数据流、性能策略和扩展边界。内容对应当前工程代码，不是产品规划文档。

## 1. 技术架构

项目最低支持 iOS 15，使用 Swift 5.9，通过 Swift Package Manager 分为两个模块：

- `YKImageEditorCore`：图片几何变换、混合、马赛克、液化、导出和编辑历史，不依赖具体编辑界面。
- `YKImageEditorUI`：SwiftUI 编辑器、状态管理，以及承载精确手势和图片图层的 UIKit 视图。

主要职责如下：

| 层级 | 主要类型 | 职责 |
| --- | --- | --- |
| 对外入口 | `ImageEditorView`、`ImageEditorViewController`、`yk_presentImageEditor` | SwiftUI/UIKit 接入、完成与取消回调 |
| 界面状态 | `ImageEditorViewModel` | 工具切换、预览状态、异步任务、提交和导出 |
| 画布与触摸 | `EditorCanvasView`、各 Tool View | 图片布局、涂抹、遮罩、贴纸/文字手势 |
| 编辑会话 | `EditorSession` | 当前工作图、撤销栈、重做栈、脏状态 |
| 图片算法 | `ImageGeometry`、`ImageBlender`、`MosaicProcessor`、`LiquifyProcessor` | 生成新的位图结果 |

SwiftUI 负责页面结构和工具面板；涂鸦、裁剪框、马赛克遮罩、液化笔刷等需要连续触摸跟踪的部分由 UIKit 实现，再通过 `UIViewRepresentable` 接入 SwiftUI。

## 2. 编辑数据流

一次编辑会话遵循以下流程：

1. 输入 `UIImage` 先通过 `ImageGeometry.normalizedOrientation` 消除 EXIF 方向差异。
2. 图片按 `ExportOptions.maxDimension` 限制最长边，得到会话工作图。
3. 涂鸦、文字、贴纸和液化笔画记录为轻量、可逆的操作。
4. 裁剪、Blend/Tone 滤镜、马赛克和已确认的液化生成新的 `UIImage` 位图检查点。
5. 顶部撤销/重做按操作发生顺序统一处理轻量操作与位图检查点。
6. 导出时把可编辑图层渲染到图片副本，再按导出配置编码；源图层不会被清除。

> 注意：`maxDimension` 同时限制初始工作图和最终导出图。默认值为 4096，因此输入图片超过该尺寸时，会在进入编辑会话时降采样。

## 3. 坐标与图层约定

### 3.1 图片坐标

- 裁剪和液化使用 `0...1` 的归一化坐标。
- 归一化坐标原点位于图片左上角。
- 像素处理统一使用“第 0 行为图片顶部”的 RGBA 缓冲，避免 Core Graphics 与 UIKit 坐标方向不同造成整图翻转。

### 3.2 画布坐标

`EditorCanvasView` 使用 `.scaleAspectFit` 展示图片，并通过 `AVMakeRect` 得到图片实际显示区域 `imageFrame`。涂鸦、马赛克、文字和贴纸均放在与 `imageFrame` 等大的 `overlayContainer` 中，因此黑边不参与编辑坐标映射。

### 3.3 临时图层与位图提交

编辑过程分为两类状态：

- 位图检查点：裁剪、Blend/Tone 滤镜、马赛克和确认后的液化直接生成新的工作图，由 `EditorSession` 保存前后图片。
- 轻量操作：涂鸦保存单笔路径；文字和贴纸保存图层及手势前后状态；液化编辑期间保存形变网格快照。

`ImageEditorViewModel` 的统一操作栈决定撤销顺序，`EditorSession` 只负责其中的位图检查点。这样不需要为每一笔涂鸦或每一次文字移动保存完整图片。

## 4. 裁剪、旋转与翻转

### 4.1 裁剪界面

裁剪由 `CropEditorView` 在当前编辑页面内切换显示，不创建新的控制器或新的导航页面。当前工作图只有在点击“完成”后才提交；取消裁剪不会修改会话图片。

裁剪框由 `CropRectView` 绘制和处理手势：

- 遮罩层使用偶奇填充，在裁剪区域外显示半透明黑色遮罩。
- 边框使用主题强调色。
- 内部绘制三等分辅助线。
- 四角绘制加粗 L 形控制柄，并提供 28 pt 的触摸命中区域。
- 拖动框内部可整体移动，拖动四角可调整尺寸。
- 裁剪框最小宽高为 40 pt，且始终限制在图片显示区域内。

### 4.2 比例裁剪

当前支持自由、1:1、4:3、16:9 和原图比例。选择固定比例后，调整裁剪框时会保持宽高比；旋转图片后，“原图”比例会根据旋转后的宽高重新计算。

### 4.3 像素裁剪

界面裁剪框会先换算成相对图片的归一化矩形，再传给 `ImageGeometry.crop`。核心层把归一化矩形映射到 `CGImage` 像素尺寸，取整并调用 `CGImage.cropping(to:)`，返回方向为 `.up` 的图片。

### 4.4 旋转与翻转

- 旋转：`ImageGeometry.rotate90` 使用 Core Graphics 绕中心顺时针旋转 90 度，并交换输出宽高。
- 左右翻转：水平方向缩放为 `-1`，交换图片左侧和右侧。
- 上下翻转：垂直方向缩放为 `-1`，交换图片顶部和底部。

旋转和翻转先作用于裁剪工具自己的 `workingImage`，最后与裁剪结果一起作为一次历史记录提交。

## 5. Blend滤镜

Blend 滤镜不是 Core Image 滤镜链，而是“叠加图层 + Core Graphics 混合模式”的实现。

### 5.1 混合过程

`ImageBlender` 的处理顺序为：

1. 根据预设生成纯色、线性渐变、径向光效或纸张纹理叠加层。
2. 使用预设对应的 `CGBlendMode` 将叠加层绘制到原图。
3. 得到 100% 效果图后，再与原图按强度进行普通 Alpha 插值。

这种实现同时支持纯色和图片叠层。公开的 `ImageBlendMode` 覆盖正片叠底、滤色、颜色加深、叠加、柔光、强光、差值、排除、色相、饱和度、颜色和明度等模式。

### 5.2 内置预设

`BlendPreset` 当前提供暖色加深、柔光渐变、叠加光感、强光渐变、纸感压暗、滤色暖光、加光、橙色色相、青绿着色、排除撞色和提饱和。

### 5.3 预览性能

- 工具预览最长边限制为 1080 像素。
- 预设缩略图最长边限制为 160 像素。
- 预览先缓存 100% 效果图，强度滑杆仅调整预览层透明度，因此滑动时不重复执行完整混合。
- 预设切换和缩略图生成在后台队列执行。
- `generation` 标识用于丢弃已经过期的异步结果，防止快速切换预设时旧结果覆盖新结果。
- 点击应用后，使用当前会话图片在后台生成最终结果，再回到主线程提交。

## 6. Tone滤镜

Tone 滤镜是独立于 Blend 滤镜的参数调色工具，使用 Core Image 处理以下参数：

| 参数 | 内部范围 | Core Image 映射 |
| --- | --- | --- |
| 曝光 | `-2...2 EV` | `CIExposureAdjust` |
| 亮度 | `-1...1` | `CIColorControls.inputBrightness` |
| 对比度 | `-1...1` | 映射为 `CIColorControls.inputContrast` 的 `0...2` |
| 饱和度 | `-1...1` | 映射为 `CIColorControls.inputSaturation` 的 `0...2` |
| 色温 | `-1...1` | `CITemperatureAndTint`，目标色温约 `4000...9000K` |
| 高光 | `-1...1` | `CIToneCurve` 的 75% 灰度控制点 |
| 阴影 | `-1...1` | `CIToneCurve` 的 25% 灰度控制点 |

所有参数以 `0` 为中性值，并由 `ToneFilterParameters` 统一保存。处理顺序为曝光、高光/阴影、色温、亮度/对比度/饱和度，预览和最终应用都调用 `ToneFilterProcessor`，避免两条链路效果不一致。

Tone 面板使用一个滑杆编辑当前选中的参数，底部横向切换七个参数。预览图最长边限制为 1080 像素；快速拖动时只串行处理最新参数，过期结果不会覆盖新预览。点击应用后处理完整工作图，并作为一个位图检查点进入撤销历史；取消或重置不会提交图片。

## 7. 涂鸦

涂鸦由 `DoodleDrawView` 处理：

- 单指触摸生成 `UIBezierPath`。
- 笔画使用圆形端点和圆形连接，默认宽度为 6 pt。
- 当前笔画通过 `CAShapeLayer` 实时显示，避免每次移动都重绘整个视图。
- 每条已完成路径保存其颜色，切换颜色不会影响已有笔画。
- 当前内置颜色为红、橙、黄、绿、蓝、白、黑。

每条已完成笔画都会作为一个 `DoodleStroke` 进入操作历史。撤销会按标识移除最后一笔，重做会恢复同一个笔画对象。切换工具不会把涂鸦烘焙进底图；导出时才按工作图尺寸渲染到输出副本。

## 8. 文字

文字输入使用 SwiftUI Alert 中的 `TextField`。添加后由 `OverlayFactory.textOverlay` 创建 `UILabel`：

- 默认使用 28 pt 粗体系统字体。
- 支持多行和居中对齐。
- 使用当前颜色面板选中的颜色。
- 初始位置位于图片中心。

文字承载在 `TransformableOverlayView` 中，支持：

- 单指拖动位置。
- 双指捏合缩放。
- 双指旋转。
- 多个手势同时识别。

添加文字会记录一条图层新增操作。一次连续的拖动、缩放或旋转手势结束后，记录手势开始和结束状态；撤销只恢复这一次手势。点击应用只退出当前工具，不销毁文字图层。导出时文字会栅格化到输出副本，但编辑会话中的源图层仍然保留。

## 9. 贴纸

贴纸素材不由组件内置，调用方需实现 `StickerProviding`，或使用 `ClosureStickerProvider` 返回 `[UIImage]`。未提供素材或素材数组为空时，即使启用了 `.sticker`，工具栏也会自动隐藏贴纸入口。

贴纸选择使用 SwiftUI 网格。选中后创建边长为 120 pt 的图片叠加层，并复用文字图层相同的拖动、缩放和旋转逻辑。

### 9.1 图片渲染模式

贴纸进入编辑器时会统一解析渲染模式：

- 已是 `.alwaysOriginal` 的图片保持调用方指定颜色。
- SF Symbol 或模板图使用编辑器强调色，并转换为 `.alwaysOriginal`。
- 普通位图只转换为原色渲染，不改变图片自身颜色。

该处理同时用于选择网格和画布贴纸，避免模板图在深色按钮环境中继承黑色 tint。

### 9.2 提交方式

贴纸在整个编辑过程中保持为独立视图，并与文字一样记录新增和单次变换操作。裁剪、滤镜、液化及导出不再清除源贴纸；导出得到的是栅格化副本，原贴纸仍可继续拖动、缩放和旋转。

## 10. 马赛克

马赛克采用“笔刷遮罩 + 全图像素化 + 遮罩合成”的方式。

### 10.1 遮罩绘制

`MosaicMaskView` 使用 `UIBezierPath` 记录用户涂抹区域：

- 默认笔刷宽度为 28 pt。
- 编辑时用半透明白色显示命中区域。
- 提交时按工作图尺寸和 scale 生成白色遮罩；透明区域表示不处理，白色区域表示应用马赛克。

### 10.2 像素化算法

`MosaicProcessor.pixelate` 将图片转换为顶部优先的 RGBA 缓冲。每个方格读取中心像素颜色，并用该颜色填充整个方格。UI 提交时的方格边长为：

```swift
max(8, Int(imageWidth / 60))
```

处理完整图后，通过遮罩只把马赛克结果合成到用户涂抹区域，其余区域保留原图。该操作作为一个历史状态提交。

## 11. 液化

当前液化只实现推移模式，核心由 `LiquifyDeformer` 和 `LiquifyProcessor` 组成。

### 11.1 手势采集

`LiquifyBrushView` 只响应图片实际显示区域内的单指拖动：

- 触摸点和移动向量转换为左上原点的归一化坐标。
- 笔刷半径相对图片短边计算，避免横图和竖图上的笔刷视觉尺寸不一致。
- 界面可调整半径和力度，并用虚线圆显示当前笔刷范围。

### 11.2 形变场

编辑器使用 56 x 56 单元的规则网格记录反向位移。每次推移只更新笔刷半径内的网格点，并使用余弦函数从中心到边缘平滑衰减：

```text
falloff = 0.5 * (1 + cos(pi * distance / radius))
```

“反向位移”表示每个输出像素应该从原图哪个位置采样，这种表示可以直接用于最终重采样，减少推移后出现空洞的概率。

### 11.3 图片重采样

`LiquifyProcessor` 对每个输出像素执行以下步骤：

1. 将输出像素位置转换成归一化坐标。
2. 对网格位移场做双线性插值，求出源图采样位置。
3. 对源图片 RGBA 像素再次做双线性采样。
4. 写入新的 RGBA 缓冲并生成 `UIImage`。

### 11.4 预览性能

- 实时预览最长边限制为 560 像素。
- 形变场先创建快照，再交给后台队列渲染，避免主线程写入和后台读取发生竞争。
- 若前一次预览尚未结束，只记录“仍需更新”，完成后立即渲染最新状态，不为每个触摸事件无限排队。
- 点击应用后对完整工作图执行最终渲染。
- 每次液化手势开始时保存约 26 KB 的 56 x 56 网格快照，手势结束后保存结果快照；撤销和重做通过恢复网格完成，不保存完整预览位图。
- 点击应用后，当前液化笔画历史会折叠成一个最终位图检查点；取消液化则丢弃本次液化操作。

液化属于 CPU 逐像素操作，是当前计算量最大的功能。超大图片的最终应用耗时主要取决于 `maxDimension`。

## 12. 撤销、重做与工具切换

历史采用“轻量操作 + 位图检查点”的混合模型。`ImageEditorViewModel` 维护统一操作顺序，操作类型包括：

- 位图检查点。
- 单条涂鸦笔画。
- 文字/贴纸新增。
- 文字/贴纸单次变换前后状态。
- 单笔液化前后的形变网格。

其中 `EditorSession` 继续使用两个 `[UIImage]` 数组维护位图检查点：

- `commit`：当前图进入撤销栈，新图成为当前图，重做栈清空。
- `undo`：撤销栈末项成为当前图，原当前图进入重做栈。
- `redo`：重做栈末项成为当前图，原当前图进入撤销栈。

撤销或重做时，统一操作栈先确定操作类型，再恢复对应轻量状态或调用 `EditorSession`。切换工具时：

- 涂鸦、文字和贴纸保持独立可编辑，不因切换工具而合并。
- 离开马赛克时应用当前遮罩并创建位图检查点。
- 进入裁剪、滤镜或液化不会清除可编辑图层。
- 取消滤镜或液化只清除预览，不提交图片。
- 液化编辑期间可逐笔撤销；确认后折叠为一次位图操作。

轻量操作不会复制完整图片，但位图检查点当前仍没有数量或内存上限。若用于长时间、高分辨率编辑，应为 `EditorSession` 增加位图检查点上限或按内存压力清理较早检查点。

## 13. 导出

导出由 `ImageExporter` 完成：

1. 应用尚未提交的马赛克遮罩。
2. 把涂鸦、文字、贴纸等可编辑图层渲染到工作图副本。
3. 按 `ExportOptions.maxDimension` 再次检查最长边。
4. 根据 `preferJPEG` 输出 JPEG 或 PNG 数据，再构造最终 `UIImage`。

渲染过程不会删除或修改源图层，因此即使宿主在导出回调前继续保留编辑会话，文字和贴纸仍可单独编辑。

默认配置：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `maxDimension` | 4096 | 工作图和导出图最长边限制；非正数表示不限制 |
| `jpegQuality` | 0.9 | JPEG 压缩质量，初始化时限制在 `0...1` |
| `preferJPEG` | `true` | `true` 使用 JPEG；`false` 使用支持透明度的 PNG |

完成时返回 `.finished(UIImage)`，取消或放弃时返回 `.cancelled`。UIKit 包装入口保证 completion 在主线程执行。

## 14. 功能开关与接入

`EditorFeature` 是 `OptionSet`，支持按需组合：

```swift
let cropAndText = EditorConfig.including([.crop, .text])
let withoutMosaic = EditorConfig.excluding([.mosaic])

let exportOptions = ExportOptions(
    maxDimension: 2048,
    jpegQuality: 0.85,
    preferJPEG: true
)
let config = EditorConfig(features: [.crop, .blend, .tone, .sticker], exportOptions: exportOptions)
```

SwiftUI 接入：

```swift
ImageEditorView(
    image: image,
    config: config,
    stickerProvider: stickerProvider
) { result in
    // 处理 finished 或 cancelled
}
```

UIKit 接入：

```swift
presentingViewController.yk_presentImageEditor(
    image: image,
    config: config,
    stickerProvider: stickerProvider
) { result in
    // 回调位于主线程
}
```

## 15. 扩展新功能

新增编辑工具通常需要完成以下位置：

1. 在 `EditorFeature` 增加功能位。
2. 在 `EditorTool` 增加标题、图标和功能映射。
3. 在 `ImageEditorView` 增加对应工具面板。
4. 在 `ImageEditorViewModel` 管理工具状态、预览、取消和应用流程。
5. 将可复用算法放入 `YKImageEditorCore`，不要耦合界面状态。
6. 最终结果通过 `EditorSession.commit` 提交，确保撤销/重做行为一致。
7. 为核心算法补充像素方向、尺寸、边界值和功能开关测试。

如果新功能需要实时手势，优先复用 `EditorCanvasView` 的图片显示区域和归一化坐标约定；如果处理成本较高，应采用低分辨率预览、后台最终渲染和过期任务丢弃策略。
